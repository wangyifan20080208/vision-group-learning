## 1. 坐标系

从 CAD 解析得到（已用 `diag_axis.py` 验证）：

| CAD 轴 | 含义 | 范围 |
|---|---|---|
| X | 场地长边（12.6 m） | −6.30 ~ +6.30 |
| **Y** | **高度（向下为正）** | **+0.100（最低）~ −0.500（墙顶）** |
| Z | 场地短边（8.6 m） | −4.30 ~ +4.30 |

**转换关系：**

```
map_x = CAD_X
map_y = CAD_Z
高度  = −CAD_Y        ← 注意 Y 轴向下
```

栅格地图：`272 × 192` 格，分辨率 `0.05 m`，原点 `(-6.8, -4.8)`

## 2. 场地高度分层（实测）

| 高度（离地） | 内容 |

## 3. 三个控制区（精确坐标）

| 控制区 | x 范围 | y 范围 | 尺寸 | 中心 | 高度 |
|---|---|---|---|---|---|
| 红方高地控制区 | −3.50 ~ −1.50 | −1.00 ~ 3.06 | 2.00 × 4.06 m | **(−2.50, 1.03)** | 0.20 m |
| 中央控制区 | −1.50 ~ 1.50 | −1.50 ~ 1.50 | 3.00 × 3.00 m | **(0.00, 0.00)** | 0.00 m |
| 蓝方高地控制区 | 1.50 ~ 3.50 | −3.06 ~ 1.00 | 2.00 × 4.06 m | **(2.50, −1.03)** | 0.20 m |

**布局特点：**

- 三个控制区在 X 方向**连成一条带**：高地 − 中央 − 高地，彼此相邻
- 两个高地绕原点 **180° 中心对称**（不是镜像对称）
- 中央控制区与地面齐平，可正常驶入

## 4. ⚠️ 关键发现：高地是 0.2 m 垂直台阶，没有坡道

用 `check_highland_access.py` 扫描了高地周边所有面：

```
[H1] 倾角 90.0°  高度 -0.200→+0.000  水平跨度 3.980m  X[-3.50,-3.50] Z[-1.00,2.98]
[H2] 倾角 90.0°  高度 -0.200→+0.000  水平跨度 3.980m  X[ 3.50, 3.50] Z[-2.98,1.00]
```

**高地的四边全部是 90° 垂直面。** 唯一的斜面是 6 cm 高的倒角（防止刮伤，不是坡道）。

### 这意味着什么

按规则，**高地控制区就在高地上**（3.3.5.1「高地增益点兼高地控制区」）。

所以：

> **底盘爬不上 0.2 m 台阶的哨兵，永远无法控制两处高地控制区。**

而按控制度机制（详见 `docs/方案_哨兵全自动_导航与自瞄.md`）：

| 能控制几处 | 后果 |
|---|---|
| 0 处 | 必输 |
| **1 处** | 只能比控制度大小，**无法速胜** |
| **2 处** | 对方每秒扣 2 点，300 秒扣 600 点 → **直接归零获胜** |

**爬不上 0.2 m，就永远只能控制 1 处（中央），战略上被锁死。**

### 建议

**把「1 台能爬 0.2 m 垂直台阶」列为哨兵的机械一级需求。**

参考：20 kg 的车爬 0.2 m，举升做功 = 20 × 9.8 × 0.2 ≈ 39 J。按 100 W 底盘功率上限算，
满功率 0.39 秒即可完成——**功率不是瓶颈，抓地力和轮径才是**。

## 5. 导航航点

因为当前地图把 0.2 m 高地标为障碍，航点分两种模式：

```json
{
  "name": "center",
  "x": 0.0, "y": 0.0, "z": 0.0,
  "mode": "on_zone"          // 直接开到区域内
}
```

```json
{
  "name": "red_highland",
  "x": -0.95, "y": 0.269, "z": 0.2,
  "zone_center": [-2.5, 1.03],
  "mode": "approach"          // 底盘爬不上去，只能停在旁边
}
```

| 航点 | 坐标 | 模式 | 说明 |
|---|---|---|---|
| 中央控制区 | (0.00, 0.00) | on_zone | 场内 93% 可通行 |
| 红方高地 | (−0.95, 0.27) | approach | 高地靠中心一侧的安全停车点 |
| 蓝方高地 | (0.95, −0.27) | approach | 同上 |

**注意**：两个高地的 `approach` 点落在中央控制区边缘——因为那确实是离高地最近的可行驶地面。
一旦底盘能爬 0.2 m，航点应改为 `zone_center`，并且**需要用更高的高度阈值重新生成地图**
（把高地判为可通行）。

## 6. 怎么重新生成

```bash
# 底盘不能爬台阶（当前默认）
python3 tools/mark_zones.py maps/rmul2027/map.yaml maps/rmul2027 -x 0

# 底盘能爬台阶（航点直接给控制区中心）
python3 tools/mark_zones.py maps/rmul2027/map.yaml maps/rmul2027 -x 1
```

参数：

| 位置 | 含义 |
|---|---|
| 第 1 个 | `map.yaml` 路径 |
| 第 2 个 | 输出目录 |
| 第 3 个 | `-x` = 红方在 −X 侧；`+x` = 红方在 +X 侧 |
| 第 4 个 | `0` = 不能爬 0.2 m；`1` = 能爬 |

### ⚠️ 红方在哪一侧需要核对

CAD 模型是**完全 180° 对称**的，从几何上无法判断哪边是红方。

当前默认 `red_side = "-x"`，**需要与官方场地图（规则手册 图 3-1 / 图 3-4）核对一次**。
如果反了，把参数从 `-x` 改成 `+x` 重新生成即可。
